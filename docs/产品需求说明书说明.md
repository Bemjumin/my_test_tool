# 产品需求说明书

只手写这一份。确认、开发和测试都从它出发。

格式按[产品需求文档模板](https://www.woshipm.com/pmd/933896.html)的章节来：首页、修订记录、引言、项目概述、业务需求、附录、签字。模板不抄那篇文章的正文。目录可以在 Word 里用标题生成，模板里不预置目录页。

模板是 [templates/产品需求说明书模板.docx](../templates/产品需求说明书模板.docx)。填好的例子是 [templates/产品需求说明书示例.docx](../templates/产品需求说明书示例.docx)，例子仍是「报销录入」。重新生成这两份文件：

```bat
python -m pyqt_agent.product_spec
```

首页不设页眉页脚，从第 2 页起才有。正文是宋体、五号、1.5 倍行距。

## 章节里多出来的表

文章本身没有 exe，也没有可以拿来判定对错的例子。下面这些加在对应章节里，确认和测试才不会自己编结果。

- 引言 / 定义：术语、含义、界面叫法。屏幕上的名字和口头说法不一样时，写在「界面叫法」。
- 项目概述 / 运行方式：exe 文件名、主窗口标题、如何启动、启动参数、如何退出、工作目录、是否需要登录、测试账号、分辨率，以及输入和输出文件。
- 业务需求 / 不可接受的现象：出现就说明这版不能接受的情况，例如按钮在不该能点的时候仍能点。
- 业务需求 / 业务规则：要核对的计算，必须带输入样例和应显示的结果。
- 每条功能：流程表的「适用」只能填合法、非法、边界、全部。数据项除了字段、字段类型、数据来源、备注，还要写必填、合法例子、非法例子、边界。界面表写功能路径、会看到什么、适用。

没写的预期，测试会记成「需求未写，未测」。

## 附录

附录开头有一句：仅供参考，不作为正式需求，不作为验收标准。

客户确认单可以引用附录，但不会把它编成要勾选的条目。编程不实现附录。测试需求书也不收录附录。

## 在本机打开

```bat
agent serve
```

浏览器打开 http://127.0.0.1:8765 。需求阐述、开发和测试在页面上分别提交，路径写这台电脑上的文件。

需求阐述把正文改写成客户能看的说法：你会做什么，这时你会看到什么。客户在确认表填写「是这样」「不是这样」或「我要补充」。客户有不同意见时，改产品需求说明书，再生成一次确认单。重新生成会把结论恢复成「（待确认）」。

开发读取确认表。只要有一条不是「是这样」，就拒绝开发。全部是「是这样」之后，才把正文交给 Cursor 在输出目录里写 PyQt 程序。确认单只用来判断客户是否同意，编程读的是产品需求说明书正文。

测试会先写出现在这套 12 节测试需求说明书，说明见 [需求书填写说明.md](需求书填写说明.md)，再按它和 exe 做原来的四项测试。点击窗口需要在 Windows 上运行。

下面的命令和页面做同一件事，可以单独用：

```bat
agent product --requirements 产品需求.docx --out 客户确认.docx
agent code --requirements 产品需求.docx --confirmed 客户确认.docx --out 产品目录
agent test-agent --requirements 产品需求.docx --exe C:\apps\ExpenseEntry.exe --out reports\run1
```

已经写好的测试需求书，仍用 `agent confirm` 和 `agent test`。
